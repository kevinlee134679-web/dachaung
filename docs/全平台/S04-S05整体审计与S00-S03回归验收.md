## 3. 六个验收场景

1. **核心用药。** 实际 Edge 开启空库，甲提交八题及未知/不适用答案，生成描述性画像。药品、草稿、本人确认生成四条日程。本人的已服、未服和延迟均从对应时段卡提交，随后追加更正其中一项为未知。A 摘要统计的五类次序为本人已服、报告未服、延迟、其他证据、未知，实际为 1/1/0/0/1，分母 3。第四剂在截止时未到时，随后生成一条正式提醒。使用审计时钟驱动安全到时，通过既有维护与 A36 接口提交一次，实际 A 执行收到 `submitted`，页面明确无送达回执。O/A/B 行和接口状态均核对。
2. **支持到正式服务及三维反馈。** B 实际 mock 显示一般支持/资料不足，极简保留导航，邀请拒绝后保存状态。Edge 的服务及反馈两次运行通过复制刚完成的隔离库衔接同一 `service_id`，核对草稿本人确认、受控 A 派发、C 状态 `submitted → in_progress → completed`、三维反馈修订 1/2 和 A/B 所读当前来源。独立实际 HTTP 验收用同库的 `session_id → generation_id → service_draft_id → confirmation_ref_id → referral_id → service_id → execution_id → feedback_id` 串联 B23 与 C07，B24 同步读取 C 实际状态。
3. **匿名同辈。** Edge 两位本人验证待处理/受理、两份模拟成员、两篇待审及审核后的可见/隐藏，换会话恢复原成员。甲撤销共享并退出，历史保留，乙仍有独立成员。家属不能用 C41 恢复被照护者的匿名成员，旧游标、链接和回执由专项重新验证。
4. **正向积分与兑换。** Edge 核奖实际写入 34 条正向流水共 83 分。两次 C28 消费 30 和 40 分，复验原操作复用订单。数字交付实际可下载。另一单 C31 先记录未知，保留原扣减，随后可信明确未交付仅退回 40，原扣减仍在。两笔订单和实际账本核对余额 53，乙为 0。
5. **家庭精确授权。** Edge 验证本人真实绑定、授权家属读取正式安排和支持对话、家属无发言及模式切换能力、撤销后直达原会话为 403。单库 HTTP 复验覆盖 O 计划、A 来源与摘要、B 会话、C 服务、反馈、余额、订单八个旧路径，家属获准时分别可读，撤销后均为 403，乙为 404。分页、旧回执及最小投影见专项。家属获得积分查询权限后，兑换与数字内容原文仍由本人控制。
6. **失败恢复。** 实际 Edge 丢弃已提交 C07 和 C13 响应，分别使用原草稿和历史查证，只保存一次事实。SQLite 独立持有写锁时 C28 返回 503，无订单，解除锁后同键只扣一次，重新装载实际应用后原回执恢复。C31 的重复回执只退一次。并发、预算、超时、事务故障和平台各关键状态由自动化专项独立覆盖。

实际 Edge 共五组 46 个验收场景、846 条浏览器 API 响应，另有 C31 独立模拟回执。通过浏览器调试接口驱动真实页面；隔离时钟、提醒显式维护、提供方回调及上述独立 HTTP 复验均在本机执行。人工前台、真实外部系统和生产身份登录未进行。测试数据库、脱敏请求、业务引用及截图留在本机证据目录。
