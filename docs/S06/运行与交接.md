## STAR 与单次模式

默认保留 `DIALOGUE_PIPELINE=single_pass`。新库也可明确使用 `star`；已有库中的模型选择优先于进程默认值。演示管理员在「我的」的控制台可选择 mock STAR、切回 mock single_pass 和执行零网络探测。患者沿用同一个会话 API。

STAR 依次执行 state、topic、strategy、最多两个候选和 select，默认六次逻辑调用；共用最多 8 次尝试、2 个候选和 60 秒截止。真实网络尝试与 mock 逻辑调用分开统计。所有底层重试计入原预算，配置和原输入保留，未知结果不自动重试。明确中途失败可使用原消息、原检查点和剩余预算续跑。

默认 `STAR_ALLOW_SINGLE_PASS_FALLBACK=false`。预先明确设为 true 才允许在剩余预算和原时限内降阶；`requested_pipeline`、`actual_pipeline`、`fallback_reason` 均保存，供应商/模式不变，不把真实失败换成 mock。历史窗口由 `DIALOGUE_HISTORY_LIMIT` 控制，默认20，上限100。话题结构独立保存于 `data/demo/star_topics.json`，版本及内容指纹写入原轮来源。

每步与发布前重查当前会话、归属、计划、摘要及知识有效性。来源变化或关闭会话会阻止发布。检查点仅保存经校验的业务状态、候选和索引，不存储模型内部推理链。该 STAR 编排独立实现，没有复制未核许可的 CAMI 代码；准备程度的 preparing/acting/maintaining 是项目适配，不表示临床有效。

## 显式运行器

普通 serve、导入、健康页和 GET 都不启动任务。使用同一解释器、模式和绝对 DATABASE_PATH，先检查 db-status，再显式执行：

```bash
.venv-3.14/bin/python -B -X utf8 -m medplatform run-worker --once
.venv-3.14/bin/python -B -X utf8 -m medplatform run-worker
```

Windows 使用实际虚拟环境的 `Scripts/python.exe`。默认 `RUNNER_POLL_SECONDS=5`、`RUNNER_MAX_TASKS=100`。每个规范数据库路径只有一个运行器文件锁，进程退出自动释放，锁文件无需删除。已有运行器时第二进程返回 `RUNNER_ALREADY_RUNNING`。Ctrl+C 或 SIGTERM 正常停止；启动失败核对原进程和原库，不使用 killall 或删除运行库。

运行器调用既有 A 维护与执行，不另建调度事实。领取保留90秒租约、15秒续租和递增令牌；工作在长写锁外进行。+7/+28天节点基于 O 的原 enrollment_at、原24小时时窗，同节点不因重启或规则变化重复。过窗只记录 missed，不补旧邀请。邀请只为 pending，不代写患者消息，不代表展示、接受或送达。

模式、建议、邀请到期由显式维护保存；原模式2小时和本人明确恢复保持。纯本地节点中断可在原尝试记录和60秒安全间隔后恢复；服务/外部在途结果未知不重新排队。C 仍维护唯一正式服务和账本，B 读取 C 的当前状态。

## 规则与知识版本

`data/demo/support_rules.json` 登记技术规则。内置 support-default 默认关闭状态事件；support-explicit-needs 只响应用户实际保存的 support_need 自报，按24小时技术频控和来源去重生成可拒绝的邀请。不会根据一次缺记录、设备数据或心理词自行定级，也不切换 UI、发布计划或修改授权。

首次明确登记、读取、选择和回退示例：

```bash
.venv-3.14/bin/python -m medplatform seed-support-rules
.venv-3.14/bin/python -m medplatform support-rule-status
.venv-3.14/bin/python -m medplatform select-support-rule --profile-id support-explicit-needs --expect-revision 0 --confirmed
.venv-3.14/bin/python -m medplatform select-support-rule --profile-id support-default --rule-version s06-support-v1 --expect-revision 1 --confirmed
```

把 expect-revision 替换为实际读取的修订。登记相同版本同内容幂等，异内容拒绝；同一 profile 可追加新版本。新增版本需要显式选择才生效，选择记录不可冒充模型或医学审核。旧节点保留原规则快照；关闭状态规则取消 pending，接受与响应历史保留。当前数值是已确认的通知/负担工程参数，不是临床阈值。

医学知识继续要求可信审核资格，演示管理员不能伪造 reviewed_by/at。草稿、撤回、无结果、版本冲突以及资料中的指令均按原过滤和引用校验处理。支持强度映射仍显示 not_configured/null；依赖该方法的自动分级干预任务明确拒绝，不拿 none 冒充未配置。真实模式、外部身份/签名/机构及真实模型连通性仍未验证或未接入。
