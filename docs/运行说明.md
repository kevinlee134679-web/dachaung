## 安装与启动（Windows PowerShell）

已实测 Windows x64、CPython 3.14.10、SQLite 3.50.4。`requirements.in` 是直接依赖说明，`requirements.txt` 锁定本次验证的全部19个包；httpx2仅供测试。其他Python/系统组合未验证。不要使用上层研究资料目录作为应用根目录。

```powershell
Set-Location -LiteralPath 'D:\大学\大创\dachaung'
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/setup.ps1
# 不需要自定义时不创建 .env；需要时复制无密钥示例并仅本地修改。
# Copy-Item -LiteralPath '.env.example' -Destination '.env'
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/run.ps1 -Command init-db
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/run.ps1 -Command serve
```

安装脚本默认使用PATH中的 `python`；可用 `-Python 'C:\完整路径\python.exe'` 选择解释器。策略Bypass仅针对这一次脚本进程，不改变系统策略。安装依赖需要网络，TLS/下载失败时保留本地成果，网络恢复后重跑；不要关闭证书验证。本轮另在全新 `.venv-repro` 用下载好的同版本wheel离线安装复验，wheel和虚拟环境不上传。

打开 <http://127.0.0.1:8000/>，同源加载本地CSS/JS。Ctrl+C关闭。实际主入口为 `python -X utf8 -m medplatform serve`，单进程、单服务、仅监听127.0.0.1；不启动模型、调度、推送或训练。不要改为公开网络监听或当作生产认证系统部署。

最小检查：`Invoke-RestMethod 'http://127.0.0.1:8000/api/v1/health'`。健康接口无需登录；空库未初始化、schema过旧或被修改时返回503四字段错误，网页仍可显示“未就绪”。普通导入、应用工厂、启动、GET检查均不建库、不执行迁移。schema就绪只说明S01必要存储就绪，不代表O/A/B/C业务可用。

## 数据库生命周期

- `init-db`：唯一显式创建入口，默认 `var/app-demo.sqlite3`。空库从0001升至0002；已管理的同版本库重复运行保持数据；不会覆盖有未知表的库，不支持降级。
- `migrate`：对已存在的受管理数据库显式升级；缺库时报错，不悄悄建库。新增结构必须添加 `0003_*.sql` 等新文件；0001/0002提交后不改写。
- `db-status`：只读检查迁移名、顺序、父版本、原字节SHA256、最新版本及必要表。
- `DATABASE_PATH` 相对工程根目录解析；默认目录由显式初始化创建。升级前停服务并备份完整运行库；迁移失败在同一事务中回滚DDL、数据及版本行，保留原数据。未知库、校验和不符或更新版本需人工核对，不删除重建。

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/run.ps1 -Command db-status
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/run.ps1 -Command migrate
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/test.ps1
```

测试自动生成两名虚构患者及来源、时段、指标、更正数据，全部位于 `test-output/` 下的独立临时目录；不读取真实资料或默认运行库。无公共录入接口，S01不提供伪装成业务录入的模拟成功按钮。

## 配置和身份边界

`.env.example` 不含凭据。环境变量优先于 `.env`，未配置使用demo/mock/single_pass。PORT有效范围1—65535，HOST固定127.0.0.1；Host/Origin仅允许对应端口的localhost或127.0.0.1。配置不合法、production、AUTH_MODE=external或LLM_MODE=real均拒绝启动；真实模式不会回退为mock。S01没有任何模型客户端或付费请求。DIALOGUE_PIPELINE可以登记请求的配置，但当前两个执行管线都未实现；G02如实报告能力关闭、连接未验证。

身份骨架由可信服务代码注入虚构Account、关联及精确Scope；随机会话仅保存token/CSRF的哈希，8小时绝对过期，检查撤销和当前授权。**默认启动没有账号、会话或公开登录接口，G02返回401是预期状态**；管理员正常响应通过隔离测试中的可信适配注入验证，不能通过请求体、account_id头或自填Cookie冒充。身份骨架是进程内演示适配，重启即丢失；不是S02的持久化登录/家庭授权成品。

未来模块使用 `app.state.registry.include_router(app, router)` 登记已完整定义的HTTP路由；接口/操作名冲突报错，不静默覆盖。不要登记后继续修改router或绕过registry。领域处理器必须使用O权威身份/患者Scope入口；本阶段内部 `SourceReader` 会在读取前及返回前检查当前授权，并只允许demo环境，不能直接暴露SQL或凭请求体指定来源。

API写入公共边界已检查会话、同源Origin、X-CSRF-Token和16—128字符Idempotency-Key，但S01没有生产写入路由、幂等回执或业务重放实现。S02起按已确认契约补持久会话、Cookie属性、授权和7天回执/墓碑/敏感幂等保护，并在各业务读写/执行/回调/重放处重验；不得把头格式检查当成幂等完成。

日志只记录服务端生成的request_id、方法与HTTP结果；未知异常返回通用错误，不输出原异常、查询、请求体、Cookie、数据库路径或密钥。Uvicorn访问日志关闭。当前日志输出控制台，无默认日志文件或外部遥测导出器。

## 追加工作记录

正式 `docs/工作记录.md` 只能追加；首建仅允许文件不存在。先用 `journal-snapshot` 读取原字节数与SHA256，准备独立UTF-8条目，再带两个期望值执行 `journal-append`。记录ID必须唯一连续、六章齐全；更正用新记录并写 `更正引用：Rxxxx`，不改旧条目。

```powershell
.\.venv\Scripts\python.exe -X utf8 -m medplatform journal-snapshot
# 将独立条目文件及刚读取的真实值代入，禁止照抄占位符运行：
# python -X utf8 -m medplatform journal-append --entry ENTRY --expect-bytes N --expect-sha SHA256
```

记录器使用OS排他锁、期望快照、O_APPEND及fsync，追加后核验旧字节前缀。文件变化/锁竞争时拒绝，重新读取核对后再追加，不能盲目覆盖。首建/更正/并发/旧快照拒绝均在独立测试验证，不对正式历史做破坏测试。README/版本登记同样按快照追加。提交前先验证、再追加、再显式暂存允许文件、提交develop并普通推送/核验；禁止上传.env、密钥、运行库、虚拟环境、真实患者或上层无关资料。
