# 运维与运行指南

## 环境要求与基础命令

- 后端位于 `backend/`：下文的 Python 命令在该目录执行，文件路径（`var/`、`private/`、`migrations/`、`.env` 等）均相对该目录；`pnpm` 命令在仓库根目录执行。
- 依赖 CPython 3.14（由 `medplatform/__main__.py` 与 `pyproject.toml` 约束），所有 Python 命令通过 `uv run` 执行，`devenv` 与 `direnv` 可选。
- 管理命令入口为 `uv run python -m medplatform <command>`，支持命令见 `medplatform/__main__.py`。
- 根目录脚本 `start.sh`（macOS/Linux）与 `start.cmd`（Windows）在 `backend/` 中执行 `uv run --locked python -B -X utf8 -m medplatform "$@"`，严格按 `uv.lock` 运行，生产环境使用它们；不带参数时等同 `serve`，执行 `serve` 时会先运行 `pnpm install --frozen-lockfile` 与 `pnpm build` 构建前端。

## 首次建库与启动

初始化演示库（目标库已存在时抛出 `LifecycleError` 拒绝覆盖）：
```bash
uv run python -m medplatform init-demo
```

启动 Web 服务（默认监听 `127.0.0.1:8000`，使用 `var/app-demo.sqlite3`，浏览器访问 `http://127.0.0.1:8000/`）。页面来自前端构建产物，首次启动前和前端改动后运行 `pnpm install && pnpm build`：
```bash
uv run python -m medplatform serve [--database <path>] [--port <port>]
```

查看数据库迁移版本与就绪状态（输出 JSON）：
```bash
uv run python -m medplatform status [--database <path>]
```

## 定时任务运行器

`serve` 仅处理 HTTP 请求，不运行后台任务。用药时窗物化、待执行任务处理与自报邀请需独立启动 `worker`（见 `medplatform/medication/runner.py`）。

启动持续轮询的 Worker：
```bash
uv run python -m medplatform worker [--database <path>]
```

单次轮询后退出：
```bash
uv run python -m medplatform worker --once [--database <path>]
```

- 排他锁：启动时独占 `<database>.runner.lock`（POSIX 下使用 `fcntl.flock`，Windows 下使用 `msvcrt.locking`）。已有实例运行时抛出 `409 RUNNER_ALREADY_RUNNING` 退出。
- 轮询与批量常数：轮询间隔由 `RUNNER_POLL_SECONDS` 控制（默认 5 秒），每轮最多处理任务数由 `RUNNER_MAX_TASKS` 控制（默认 100 条）。自动维护患者未来 31 天内的用药时段区间。
- 任务租约与重试：任务领取使用 90 秒排他租约（`medplatform/medication/execution.py`），续租延展 90 秒。无副作用任务允许在间隔后重试；不可重试或结果未知错误记录终态，不自动重试。
- 停机：Worker 监听 `SIGINT` 与 `SIGTERM`，完成当前步骤后释放文件锁退出。

## 备份、升级与恢复

备份与迁移前必须停止所有访问该数据库的 Web 与 Worker 进程，并在命令行传入 `--stopped`，否则命令直接拒绝执行。

备份数据库：
```bash
uv run python -m medplatform backup --stopped [--database <path>] [--output <dir>]
```
备份保存于 `private/backups/<UTC时间>-<随机ID>/`，包含在线备份的 `database.sqlite3`、附件目录 `files-demo/`、POSIX 下的密钥目录 `linux-key/`、可选 `configuration.env` 与校验清单 `manifest.json`。

执行数据库迁移：
```bash
uv run python -m medplatform migrate --stopped [--database <path>] [--target <version>]
```
迁移前强制先行备份，备份成功后在事务中按序执行 `migrations/*.sql`。DDL 失败时事务回滚。

数据恢复步骤：
1. 停止所有访问数据库的进程。
2. 核对备份目录下 `manifest.json` 的 SHA-256 校验和。
3. 将备份的 `database.sqlite3` 与 `files-demo/` 复制到目标目录。
4. 恢复保护密钥：POSIX 系统恢复至 `private/local-protection/uid-<uid>/` 且保持 UID 一致；Windows 系统需在原用户及机器上下文恢复以满足 DPAPI 要求。
5. 执行 `uv run python -m medplatform status --database <path>` 验证恢复后的数据库。

## 运行时配置

配置项以 `medplatform/core/config.py` 的 `Settings` 为准。复制 `.env.example` 为 `.env` 修改，不要提交 `.env`。`APP_ENV=production`、`AUTH_MODE` 非 `demo`、`LLM_MODE=real` 会拒绝启动。

## 常见排错

- `Database already exists` → 数据库已存在，直接执行 `serve` 或通过 `--database` 指定新文件路径。
- `503 FRONTEND_NOT_BUILT` → 前端尚未构建，运行 `pnpm install && pnpm build` 后刷新页面。
- `Stop all web, worker and other writers for this DB, then explicitly pass --stopped` → 停止访问该数据库的所有进程后追加 `--stopped` 参数执行。
- `409 RUNNER_ALREADY_RUNNING` → 已有 Worker 进程持有锁文件，停止残留进程，不要删除锁文件。
- `409 SCHEDULE_WINDOW_NOT_READY` → 所查区间的用药时段尚未物化，执行 `uv run python -m medplatform maintain --patient-id <id> --window-start <start> --window-end <end>` 后重新读取。
- `503 SENSITIVE_RECEIPT_UNAVAILABLE` → 本地载荷解密失败（`medplatform/core/protection.py`）。POSIX 下检查 UID 是否一致且 `private/local-protection/uid-<uid>` 权限为 0700、文件为 0600；Windows 下确认在加密时的同一用户与机器环境中运行。
- `SchemaError` → 数据库迁移版本落后或缺少表，停止服务后执行 `uv run python -m medplatform migrate --stopped`。
