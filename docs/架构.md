# 系统架构

## 代码包结构

后端位于 `backend/`，下列后端路径均相对该目录。

- `medplatform/core`：基础库，提供数据库连接、配置解析、结构迁移、数据备份、载荷加解密、幂等收据与异常定义。
- `medplatform/web`：FastAPI 应用装配层，提供应用工厂函数 `create_app`、中间件、模块路由分发器、契约注册表与静态资源映射。
- `medplatform/identity`：域 O 身份与权限认证，处理账号登录会话、患者切换、家庭成员绑定码兑换、健康数据授权（Grant）与第三方接收方配置。
- `medplatform/profile`：域 O 患者画像，处理问卷定义、作答校验与画像评估。
- `medplatform/medication`：域 A 用药与健康数据管理，处理用药计划制定与时段物化、多来源事件记录与质控、依从性统计聚合及任务调度。
- `medplatform/dialogue`：域 B AI 对话与干预，处理会话状态流转、模型回复生成、医学知识库检索与支持规则切换。
- `medplatform/support`：域 C 社会支持根包，提供跨子模块通用模型与辅助逻辑。
- `medplatform/support/catalog`：域 C 服务资源目录，负责资源项目与规格版本的管理与检索。
- `medplatform/support/drafts`：域 C 服务申请草案与知情同意。
- `medplatform/support/services`：域 C 正式支持服务流转、派发任务与提供方回执。
- `medplatform/support/feedback`：域 C 患者自愿服务评价与反馈。
- `medplatform/support/peer`：域 C 匿名同辈互助小组、成员映射、发言审核与公开。
- `medplatform/support/points`：域 C 积分账户、依从性周期审核与流水账本。
- `medplatform/support/rewards`：域 C 兑换品规格、积分兑换订单与履约回执。
- `medplatform/demo`：演示场景构建，提供 14 时段用药场景与 29 天积分场景的数据生成器。
- `frontend/`（位于仓库根目录）：单页前端，Solid 2 + Vite + Tailwind CSS 4 + TypeScript（typescript-native-bridge），`pnpm build` 构建到 `backend/medplatform/static`（不入库）；Vitest 用例位于 `frontend/test/`。
- `tests/`：后端测试套件，镜像模块结构，`tests/fixtures.py` 提供夹具。

## 领域映射与数据表前缀

业务划分为 O、A、B、C 四个领域与公共底座，数据表见 [数据字典](数据字典.md)。

| 领域标识 | 业务含义 | 对应代码包 | 数据表前缀与示例表 |
| --- | --- | --- | --- |
| 公共底座 | 基础技术设施与通用审计 | `medplatform/core`, `medplatform/web` | `schema_migrations`, `operation_audit` |
| O | 身份与画像 | `medplatform/identity`, `medplatform/profile` | 前缀 `o_*`，如 `o_accounts`, `o_sessions`, `o_binding_codes` |
| A | 数据与用药管理 | `medplatform/medication` | 前缀 `a_*`、`s02_*`、`s03_*`，如 `dose_slots`, `source_events`, `a_tasks` |
| B | AI 沟通与干预 | `medplatform/dialogue` | 前缀 `b_*`，如 `b_sessions`, `b_messages`, `b_records` |
| C | 社会支持体系 | `medplatform/support/*` | 前缀 `c_*`，如 `c_support_resources`, `c_services`, `c_points_accounts` |

## 路由声明、请求边界与应用装配

- 路由声明：各业务域 `api.py` 定义 `ROUTES` 列表，每条记录为 `(card_id, method, path, action, input_schema)` 元组，绑定接口契约卡编号与 Pydantic 输入校验模型。
- 请求边界与分发：`medplatform/web/routes.py` 的 `router()` 读取各模块 `ROUTES` 挂载至 FastAPI。该边界校验会话 Cookie 或集成凭据，校验路径与查询参数，通过 `medplatform/core/strict_json.py` 拒绝重复键与非标准 JSON，通过 Pydantic 校验请求体，并将响应包装在 `envelope` 中返回。
- 应用装配：`medplatform/web/app.py` 的 `create_app()` 初始化数据库连接与时钟，实例化各域服务，连接服务回调，挂载路由、静态目录与异常处理器。

## 数据库迁移规范

- 迁移文件位于 `migrations/*.sql`，命名格式为 `0001_name.sql`，序号从 `0001` 起连续递增。
- 文件内容由 SHA-256 哈希值校验（见 `medplatform/core/migrations.py` 的 `catalog`）。执行迁移时校验已应用版本的文件名、父版本与校验和，篡改会触发 `SchemaError` 拒绝执行。
- 不能修改已有的迁移文件。结构变更需新增下一个递增序号的 `.sql` 文件，通过 `uv run python -m medplatform migrate --stopped` 执行升级。
