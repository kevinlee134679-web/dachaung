# 全平台验收用例

后端测试在 `backend/` 执行 `uv run --locked python -B -X utf8 -m unittest discover -s tests`；前端测试在仓库根目录执行 `pnpm test`。代码检查在 `backend/` 执行 `uv run --locked ruff check` 与 `uv run --locked ruff format --check`，在根目录执行 `pnpm typecheck`、`pnpm lint`、`pnpm format:check` 与 `pnpm knip`。以下用例用于对照功能与验证预期。

| 用例/模块 | 前置与输入 | 步骤 | 预期及当前验证位置 |
| --- | --- | --- | --- |
| O-01 登录/退出 | `init-demo` 已执行，患者甲 | 选择虚构身份→登录→退出→用原 Cookie 读 `auth/me` | 登录 201；退出后 401；`backend/tests/identity/test_identity.py` 及真实浏览器 |
| O-02 问卷向导与卡片结果 | 单版本 `initial-cas-review-v1`，患者本人与协助家属 | 确认隐私弹窗→按向导逐题作答（含 `unknown` 与 Q4 联动、跳过选填）→提交→本人生成并查看卡片；另测家属代答、空白替代答卷与 `latest-submitted` | 本人自报 Q1–Q3 且确认同次经历时 `cas_observed` 计 3–15 分；缺项/代答/非同次经历为 `insufficient`；结果页展示按题卡片不展示 CAS 数值；家属调用 `O22`/`O32` 被拒；`backend/tests/identity/test_cas_questionnaire.py`、`backend/tests/identity/test_identity.py`、`frontend/test/features/questionnaire/questionnaire.test.tsx` |
| O-CAS 本机重训模型 | 安装 `cas` 依赖组并启用模型包 | 用 `reference_cases.json` 四例输入 Q5–Q8 预测，另测 Q8 `stable_experience="否"` 与 Q5–Q8 缺项 | 四例预测误差在 `1e-5` 内；不适任或不全返回 `insufficient`；未安装 `torch` 时跳过；`backend/tests/identity/test_cas_questionnaire.py`（`CasModelTests`） |
| O-03 用药清单与正式计划 | 已有或新增虚构药品，本人与家属 | 填写剂量/时刻/起止日→保存并生效→未改动再看按钮→模拟保存失败后重试；家属尝试确认正式计划 | 本人一次保存并发布正式计划并物化时段；未改动时按钮禁用；失败后可继续编辑重试；家属确认被拒；`backend/tests/identity/test_identity.py`、`backend/tests/medication/test_records.py`、`frontend/test/features/plan-drafts/medication-list.test.tsx` |
| O-04 家庭精确授权 | 甲生成限时单次码，家属登录 | 兑换→检查无自动 `scope`→本人只授 `dialogue:read`→家属读取→本人撤销→原家属会话再读 | 关系不等于授权；可读不能代发；撤销即时；`backend/tests/identity/test_identity.py`、`backend/tests/identity/test_auth_regressions.py`、`frontend/test/app/identity.test.tsx` 及真实浏览器 |
| A-01 五类统计/证据分离 | `medplatform.demo.medication` 隔离固定 14 时段；本人 10 条，开盒 2 条 | 打开用药报告（每次 GET 实时计算）→查看 14 分母/10 分子；开盒不算本人确认 | 比例 10/14，未关联或冲突归类准确；`backend/tests/medication/test_analytics.py`、`backend/tests/medication/test_demo.py` 及真实浏览器 |
| A-02 晚到/更正/撤回与漏服原因 | 上例已有统计 `as_of`；今日时段快捷操作 | 添加第 11 条迟到本人报告→刷新重读→按原 `as_of` 重读；记录 `not_taken` 附 `missed_reason`；`taken` 附 `missed_reason` | 当前 11/14，按原 `as_of` 重算仍 10/14；`not_taken` 保存并回显漏服原因；`taken` 带原因返回 422；`backend/tests/medication/test_records.py`、`backend/tests/medication/test_analytics_audit.py`、`frontend/test/features/dose-events/events.test.tsx` |
| A-03 租约/停机/重复执行 | 到时任务，显式 `worker` | 并发领取、旧令牌提交、SIGTERM 停止、重启、过窗、未知外部结果 | 单库单 runner；旧租约不能提交；未知不回 pending；`backend/tests/medication/test_execution.py`、`backend/tests/medication/test_runner.py` |
| A-04 AI 病历识别 | 已上传 PDF 或 PNG/JPEG 病例文件 | 未配置模型时本人/授权家属调用 `A42`；使用替身模型测图片 data URL、PDF `/files` 上传、字段校验、超时失败与无候选；清单填入缺时刻药物 | 未配置返回 `unavailable`；跨患者返回 404；缺时刻按每日次数填入默认时刻；`backend/tests/medication/test_recognition.py`、`frontend/test/features/plan-drafts/medication-list.test.tsx` |
| B-01 单次调用/危机拦截/模型适配 | mock 与替身 `LLMClient`，管理员受控案例 | 触发 `empty_response`/`invalid_json`；发送危机短语；测试 `ChatModel` 超时/空返回/用量；校验仅含 `assistant_reply` 输出与伪造引用；前端空对话点开场句 | 每轮最多 2 次尝试；危机短语返回固定安全回复且 0 次调用模型；超时为 `outcome_unknown`；伪造引用降级；`backend/tests/dialogue/test_dialogue.py`、`frontend/test/features/support/support.test.tsx` |
| B-02 失败与未知 | 已有会话 | 受控 `llm_timeout`→尝试重试与重置 | 截止时间取 `LLM_TIMEOUT_SECONDS`；超时为 `outcome_unknown`，409 不可重试/抹去；`backend/tests/dialogue/test_dialogue.py` 及真实浏览器 |
| B-03 模式/规则/知识 | 默认 `support-default`（状态事件关闭）；支持强度未配置 | 切换极简并刷新/恢复；CLI `select-support-rule --profile-id support-explicit-needs`→本人 `support_need`→worker；切回 `support-default`；尝试未审医学资料 | 模式可恢复；切回后待响应 `state_event` 邀请取消；不伪医学审核/临床阈值；`backend/tests/dialogue/test_governance.py`、`backend/tests/medication/test_runner.py` 及真实浏览器 |
| C-01 资源目录与服务草稿边界 | 目录已 seed，患者或精确授权家属 | 浏览资源目录→准备草稿；未确认直接申请；本人核对最小共享再申请 | 浏览 GET 不写；草稿不申请不通知；确认后唯一正式服务；`backend/tests/support/catalog/test_catalog.py`、`backend/tests/support/drafts/test_drafts.py`、`backend/tests/support/services/test_services.py` |
| C-02 服务流转/独立反馈 | 正式服务 `submitted` | 管理员模拟派发→`in_progress`→`completed`；重放/非法终态回退；本人三维反馈 | 服务状态权威、唯一派发，完成与效果分开；终态不倒退；`backend/tests/support/services/test_services.py`、`backend/tests/support/feedback/test_feedback.py` |
| C-03 匿名同辈 | 模拟小组可申请、有登记 moderator | 本人自愿共享/入组→显式受理→发文字待审→明确公开→`peer-memberships/me` 恢复→退出 | 未受理不能交流；公开不泄露患者 ID；退出后权限消失、历史保留；`backend/tests/support/peer/test_peer.py` |
| UI-01 首页与导航 | 已 seed，甲/乙/家属 | 1365 与 390 宽遍历五导航（首页、用药管理、药学知识、支持服务、我的）；患者切换时延迟响应 | 无全页横向溢出；旧请求响应不泄漏到新患者视图；`backend/tests/support/services/test_home.py`、`frontend/test/app/identity.test.tsx`、`frontend/test/features/home/home.test.tsx` |
| DEP-01 干净初始化/升级 | CPython 3.14 环境、锁定依赖 | `init-demo`→`status`→`serve`；再 `init-demo` 拒绝；停止写入→`backup`/`migrate`；旧库 DDL 失败 | 不自动清库；先私有备份再迁移；失败回滚；`backend/tests/core/test_lifecycle.py`、`backend/tests/core/test_migrations.py` 及 CLI 实际验证 |
| DEP-02 演示故事数据 | 空库执行 `migrate` 与 `seed` | 连续执行两次 `seed()` 并核对患者甲数据 | 产生 3 个药品、1 个计划、含 3 种 `missed_reason` 的服药记录、2 个会话（5 条助手回复）与 6 张结果卡片；重复执行幂等不变；`backend/tests/demo/test_story.py` |
| DEP-03 源码与配置校验 | 明确提交、无运行数据，校验 `Settings` | 从分支检出→环境安装→测试 `LLM_MODE=real` 缺省校验与隔离 `.env` | 运行数据与 `.env` 不入库；缺三项外部模型配置时拒绝启动；`backend/tests/web/test_foundation.py` |

输入注入、重复 JSON 键、跨患者 ID/游标、过期授权、重复幂等、乐观修订、并发/回执、文件替换和 Linux 密钥损坏由对应测试套件覆盖。真实设备、真实机构、外部身份、系统推送通知及临床医学有效性当前未接入，不作为已验收能力。
