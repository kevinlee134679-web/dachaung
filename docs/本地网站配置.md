# 本地网站配置

本分支在原平台基础上增加 CAS 问卷计分、复评画像和可选的重训模型预测。以下步骤适用于 Windows PowerShell，从仓库根目录开始。模型在本机 CPU 执行，演示账号和问卷使用本地 SQLite 数据库。

## 运行环境

| 组件 | 已验证版本或配置 | 用途 |
| --- | --- | --- |
| CPython、uv | 64 位 CPython 3.14.10，uv 0.13.9 | 后端要求 3.14.x。基础依赖由 `backend/uv.lock` 锁定 |
| Node.js、pnpm | Node.js 24.22.3，pnpm 12.22.0 | 用仓库锁文件构建网页 |
| 基础模式 | `APP_ENV=local`、`AUTH_MODE=demo`、`LLM_MODE=mock` | 本地账号、模拟对话、自报计分与规则分型使用默认设置 |
| CAS 模型预测 | NumPy 2.5.5、CPU 版 PyTorch 2.15.0，开关为 `CAS_RETRAINED_BUNDLE` | 根据本人填写的 Q5–Q8 运行本地推理 |
| 地址与存储 | 监听 `127.0.0.1`，示例端口 `8017`，默认端口 `8000` | 默认数据库为 `backend/var/app-demo.sqlite3` |

## 首次启动

克隆本分支后，安装前端和后端依赖。以下命令只需在新工作目录执行一次。前端改动后重新运行 `pnpm build`。

```powershell
git clone --branch codex/cas-review-v1 https://github.com/kevinlee134679-web/dachaung.git
Set-Location dachaung
pnpm install --frozen-lockfile
pnpm build
Set-Location backend
uv sync --locked
```

要启用与本次演示一致的预测，在同一个 `backend` 目录继续运行以下命令。只做自报计分与分型时可直接进入建库步骤。

```powershell
uv pip install --python .venv/Scripts/python.exe --torch-backend cpu "torch==2.15.0" "numpy==2.5.5"
$env:CAS_RETRAINED_BUNDLE = (Resolve-Path 'data/models/cas-dl2-retrain-20261124').Path
```

首次使用默认数据库时初始化一次。若已经在该目录使用演示库，下面的判断会保留既有账号、问卷和画像。旧版数据库提示版本不符时，按[运维指南](运维.md)备份和迁移。

```powershell
if (-not (Test-Path 'var/app-demo.sqlite3')) {
    uv run --locked python -B -X utf8 -m medplatform init-demo
}
uv run --locked python -B -X utf8 -m medplatform serve --port 8017
```

浏览器打开 [本机演示网站](http://127.0.0.1:8017/)。新建库使用仓库自带的虚构身份，已有问卷和画像存放在各自的本地库中。

## 用药安排演示

在「我的 → 药品资料」添加虚构药品后，可点「加入用药清单」。从「用药管理 → 用药清单」进入时也能选择已有药品或在清单里登记新药品。用时间选择器逐个填写服药时间，选择每天或每周指定日期。保存草稿后可返回继续编辑，点「确认并生成安排」才会发布正式计划。确认结果显示计划版本和服务端查到的首个时段，可直接跳到对应日期。打开某个时段的「记录本人的服药情况」，保存后可查看关联的服药记录。

清单内可上传或选择已保存的文字 PDF，点选经过本人核对的候选条目。预填写用药字段标签，例如「药品名称：虚构演示药」「每次剂量：1 片」「用药频次：每日两次」「服药时间：08:00、20:00」。仅将已明确写出的固定日常时刻填入，起始日期由本人选择。「每日两次」这类资料仍需根据原件核对具体时刻。扫描件、图片和未识别字段通过原件人工录入。PDF 提取在本机完成，预览接口 `GET /api/v1/files/{id}/medication-preview` 只向本人在原件读取授权下返回候选，勾选条目后仍须保存草稿和本人确认。在「用药管理 → 病例资料」可以上传、查看原件并核对用药草稿。

## 保存设置与日常启动

如需每次启动都使用同一配置，在 `backend/.env` 中设置以下两行。已有配置文件时编辑对应项；首次配置可从 `backend/.env.example` 复制一份。示例路径适用于仓库自带的启动脚本，也可以填写模型目录的绝对路径。PowerShell 进程里的同名环境变量优先生效。

```dotenv
PORT=8017
CAS_RETRAINED_BUNDLE=data/models/cas-dl2-retrain-20261124
```

保存后可从仓库根目录运行 `.\start.cmd`。关闭预测时，删除或注释 `.env` 的模型目录配置，在设过变量的 PowerShell 中运行 `Remove-Item Env:CAS_RETRAINED_BUNDLE -ErrorAction SilentlyContinue`，随后重启网站。

## 模型文件与验收

发布包位于 [backend/data/models/cas-dl2-retrain-20261124](../backend/data/models/cas-dl2-retrain-20261124/)。其中 `ensemble.pt` 是重训权重，`preprocessing.json` 是冻结的编码、变换和特征顺序，`reference_cases.json` 保存四个虚构对照样例。服务启动时校验这三个文件的 SHA-256，并重放四例；三个文件需使用本分支附带的原始字节。遇到 `CAS_BUNDLE_INVALID` 时，核对路径、文件版本和当前后端环境中的 NumPy、PyTorch。

可在 `backend` 运行下列命令，使用临时测试数据库验证四例的网页接口输出以及问卷、权限与复评回归。

```powershell
$env:CAS_TEST_BUNDLE = (Resolve-Path 'data/models/cas-dl2-retrain-20261124').Path
uv run --locked python -B -X utf8 -m unittest discover -s tests
```

在网页选择虚构患者本人，进入“我的 → 依从性类型”，展开评估问卷。如要查看预测，在 Q4 后继续填写自愿补充题，填完 Q5–Q8，并按实际经历回答 Q8 的稳定服药筛选。本人点击“提交问卷并生成画像”后，同一页的评估结果分别显示自报分和模型估计。第一组虚构模型样例的预测约为 **10.67 分**，页面应显示模型版本 `cas-dl2-retrain-20261124`。复评时可通过“问卷提交于”核对结果来源。首次引导若进入用药清单，可点“稍后再说”，再从“我的 → 依从性类型”查看。更多规则和边界用例见[CAS 接入与验收](CAS接入与验收.md)。
