### 3.2 第一次克隆

以下在PowerShell执行，会在当前用户的Projects目录创建一个**新克隆**。目标目录已存在时先核对，不覆盖。

```powershell
$workRoot = Join-Path $env:USERPROFILE 'Projects'
New-Item -ItemType Directory -Path $workRoot -Force | Out-Null
Set-Location -LiteralPath $workRoot
if (Test-Path -LiteralPath '.\dachaung') { throw '目标目录已存在，先核对已有工程，不覆盖。' }
git clone --branch develop --single-branch https://github.com/kevinlee134679-web/dachaung.git dachaung
if ($LASTEXITCODE -ne 0) { throw '克隆失败，先处理网络或访问问题。' }
Set-Location -LiteralPath '.\dachaung'
git status --short --branch
git remote -v
git rev-parse HEAD
git merge-base --is-ancestor 5f49d779392fc61b4725a97d3cf1118bd846d313 HEAD
```

最后一条退出码0表示当前历史包含本交接的S03代码基线；非0须核对分支/历史，不能假定新版代码已到本机。原电脑已有克隆则进入 `D:/大学/大创/dachaung`，先看status，不再clone到同名目录、不reset清改动。工作区干净且确需更新时才用 `git pull --ff-only origin develop`；不能快进时先检查差异并保留双方工作。

### 3.3 建立本机虚拟环境

在**工程根**执行。先确认解释器，再为新电脑建立自己的`.venv`，不要从原电脑复制虚拟环境。

```powershell
py -3.14 --version
py -3.14 -X utf8 -c "import sys,struct; print(sys.version); print(struct.calcsize('P')*8); assert sys.version_info[:3] == (3,14,10) and struct.calcsize('P') == 8"
if ($LASTEXITCODE -ne 0) { throw '需要先核对已验证的CPython 3.14.10 x64。' }
if (Test-Path -LiteralPath '.\.venv') { throw '已有.venv，先核对版本和用途，不覆盖。' }
py -3.14 -X utf8 -m venv .venv
if ($LASTEXITCODE -ne 0) { throw '虚拟环境创建失败。' }
.\.venv\Scripts\python.exe --version
.\.venv\Scripts\python.exe -X utf8 -m pip install -r requirements.txt
if ($LASTEXITCODE -ne 0) { throw '依赖安装失败，请保留错误并处理。' }
.\.venv\Scripts\python.exe -m pip check
```

期望：3.14.10、64位，pip安装锁定的21个包，最后输出`No broken requirements found.`。若没有`py`启动器，用已经核对版本的Python可执行文件替换前三条的`py -3.14`，例如 `& 'C:\实际安装目录\python.exe' --version`。若`.venv`已经存在，先核对其解释器，不盲目覆盖或认为它一定正确。

本说明直接调用`.venv`里的Python，**不用激活环境，也不用改系统执行策略**。每步确认成功再继续；安装失败先处理错误。已有 `scripts/setup.ps1`可安装依赖，`scripts/run.ps1`可启动常见命令；维护/执行的附加参数仍直接调用Python入口。依赖版本以仓库`requirements.txt`为准，不逐个安装“最新包”、不运行npm install。

不强制创建`.env`；需要固定本机配置时，确认文件不存在再从工程根复制`.env.example`为`.env`，填写自己的DATABASE_PATH/PORT。已有`.env`先保留和核对，不覆盖。APP_ENV用local，AUTH_MODE用demo，LLM_MODE用mock，DIALOGUE_PIPELINE用single_pass；LLM_API_KEY留空即可。进程环境变量会覆盖同名`.env`值，`.env`始终不上传。

第一次在线安装需要能访问包源，源码本地演示本身不调用付费API。断网交接可在有网络的**同类Windows/Python环境**先准备wheelhouse：

```powershell
.\.venv\Scripts\python.exe -m pip download -r requirements.txt -d test-output/wheelhouse-handoff
```

把该wheel目录通过合适渠道交给接手人，在其新虚拟环境中执行：

```powershell
.\.venv\Scripts\python.exe -m pip install --no-index --find-links '实际wheel目录' -r requirements.txt
.\.venv\Scripts\python.exe -m pip check
```

wheelhouse不在Git仓库内，原电脑`test-output`中的缓存不能被当作GitHub已交付依赖。安装失败保留错误，检查版本/网络/缺少wheel，不关闭TLS验证或随意解除版本锁。

## 4. 推荐本地演示：独立生成10/14→11/14

这条路径适合给接手人展示现有成果，不依赖原电脑的数据库，也不会修改默认`var/app-demo.sqlite3`。生成器已经执行建库、虚构账号、合法计划、数据接收/匹配及快照，**不要先对该目标额外init-db**。

### 4.1 一次生成并启动

在已安装依赖的工程根、同一个PowerShell窗口执行：

```powershell
$env:APP_ENV = 'local'
$env:AUTH_MODE = 'demo'
$env:LLM_MODE = 'mock'
$env:DIALOGUE_PIPELINE = 'single_pass'
$env:HOST = '127.0.0.1'
$env:PORT = '8000'
$demoName = 'handoff-' + (Get-Date -Format 'yyyyMMdd-HHmmss') + '-' + ([guid]::NewGuid().ToString('N').Substring(0,6))
$demoDb = "test-output/$demoName/demo.sqlite3"
.\.venv\Scripts\python.exe -X utf8 -m medplatform.demo_s03 --database $demoDb
if ($LASTEXITCODE -ne 0) { throw '演示生成失败，请检查输出；不要覆盖已有库。' }
$scenarioPath = [IO.Path]::ChangeExtension($demoDb, '.scenario.json')
$scenario = Get-Content -LiteralPath $scenarioPath -Raw -Encoding UTF8 | ConvertFrom-Json
$beginDate = ([DateTimeOffset]::Parse($scenario.window_start)).ToOffset([TimeSpan]::FromHours(8)).ToString('yyyy-MM-dd')
$endDate = ([DateTimeOffset]::Parse($scenario.window_end)).ToOffset([TimeSpan]::FromHours(8)).ToString('yyyy-MM-dd')
Write-Output "演示库：$demoDb"
Write-Output "报告起始日期：$beginDate；结束日期：$endDate（结束当日不含）"
$env:DATABASE_PATH = (Resolve-Path -LiteralPath $demoDb).Path
.\.venv\Scripts\python.exe -X utf8 -m medplatform db-status
.\.venv\Scripts\python.exe -X utf8 -m medplatform serve
```

期望：生成器输出`planned_dose_count=14`、`patient_confirmed_count=10`、`delivery_status=submitted`；db-status输出`schema_version=0006`；服务监听127.0.0.1:8000。首次需要存在的只是工程和依赖，生成器会创建目标的父目录。每次重新运行整段会生成另一个新库，历史库仍在，不是重置旧库。

### 4.2 浏览器中按顺序展示

1. 打开 <http://127.0.0.1:8000/>，选择**演示患者甲**，点击“管理自己的用药”。这是虚构身份选择，不是GitHub登录，不需要网站密码。
2. 点击“查看用药报告”（也可“我的→用药报告”）。把起始/结束日期改为终端刚打印的日期，点击“明确刷新统计与摘要”。
3. 检查：14有效已到时时段，10本人已服、0未服、0延期、2仅其他证据、2未知；比例71.4%=10/14。不是CAS或客观吞服验证率。日桶使用相同快照，不平均每天百分比。
4. 看指标：步数0仍是有效0；睡眠未采集保留原因；未知心率单位为不可用/待复核，不转换成正常值。B/C反馈显示未接入，摘要可为`insufficient`，不影响已有效的用药统计。
5. “用药管理→服药记录/指标记录”可查来源、质量和原始/修订历史；“提醒与执行”可查已有模拟执行。显示`submitted/已提交投递`，没有送达回执，不标记已读；维护后的过期任务不补发。

**日期常见误区：** 固定场景是生成日D之前7个完整北京时间日，即`[D−7 00:00,D 00:00)`。2026-11-17生成时应填11/10→11/17；页面默认近期范围可能是11/11→11/18，要手动改。换标签或刷新页面后日期控件可能恢复默认，应重新填写原窗口。以后接手时不要照抄本例日期。

### 4.3 补录并展示11/14

推荐新手在**同一终端**按Ctrl+C停止服务，保留`$demoDb`变量，再运行：

```powershell
.\.venv\Scripts\python.exe -X utf8 -m medplatform.demo_s03 --database $demoDb --add-late-report
.\.venv\Scripts\python.exe -X utf8 -m medplatform serve
```

回浏览器重新打开/刷新，选择或恢复患者甲，重新填**同一窗口**并明确刷新。期望：11本人已服、2其他证据、1未知、分母14，比例78.6%=11/14。迟到入口重跑仍是11，不重复增计；旧10/14不可变快照仍在数据库中，当前网页没有历史快照选择器，不要寻找一个尚未实现的切换按钮。关闭/重启同一库不会退回10/14。

若在第二个终端补录，先进入同一工程根，再把终端A打印的**实际同一个数据库路径**传给`--database`；不要另换一个新路径。生成器的`.scenario.json`须一起保留，它是迟到补录的定位清单。

生成器内部测试地址固定为127.0.0.1:8000。生成/迟到补录终端须保持`$env:PORT='8000'`，避免配置端口不一致导致HOST/Origin校验失败。服务若因占用需改8010等端口，生成完成后只在serve终端改PORT；再次补录前先停止服务并把PORT改回8000，补录完再改回服务端口。

### 4.4 停止和下次恢复

Ctrl+C停止服务。下次打开新终端，进入同一工程，重新设置第4.1节的运行模式及 **原演示库** 的`DATABASE_PATH`，直接serve；不再运行生成器、init-db或seed-demo。

PowerShell的`$env:`设置只在当前进程及其子进程生效，新终端不会继承你已经关闭的终端设置。若想每次都使用同一库，可在本机`.env`里配置，别把它提交到Git。未设置时会回到默认库，容易误以为数据丢失。

## 6. 原电脑/已有资料：恢复、备份与升级

### 6.1 原目录恢复

1. 进入已有工程，`git status --short --branch`确认代码与未提交工作；不要整目录覆盖或reset。
2. 检查`.venv`中的Python与依赖；确认正在使用的DATABASE_PATH。配置优先级是**当前进程环境变量 > 本机.env > 代码默认值**。
3. 同版本且schema已为0006：直接serve；仅因服务关掉或网页重新打开，不需init-db/seed-demo。
4. 从S01/S02旧schema升级：先停服务、备份，再migrate。`db-status`要求数据库已达到当前最新迁移；旧库执行它可能只返回受控失败，不表示库应删除。

### 6.2 先确认路径并备份

在停止全部使用该库的服务后，以下命令读取实际库路径并复制到忽略的`private/backups`下。未停止其他进程时不要把普通文件复制当一致性备份。

```powershell
$ErrorActionPreference = 'Stop'
$dbPath = (& .\.venv\Scripts\python.exe -X utf8 -c "from medplatform.config import load_settings; print(load_settings().database_path)").Trim()
if ($LASTEXITCODE -ne 0 -or -not (Test-Path -LiteralPath $dbPath)) { throw '未找到已配置数据库，请先核对配置。' }
$backupName = (Get-Date -Format 'yyyyMMdd-HHmmss') + '-' + ([guid]::NewGuid().ToString('N').Substring(0,6))
$backupDir = Join-Path 'private/backups' $backupName
New-Item -ItemType Directory -Path $backupDir -Force | Out-Null
Copy-Item -LiteralPath $dbPath -Destination $backupDir
foreach ($suffix in @('-wal','-shm','-journal')) {
    $sidecar = $dbPath + $suffix
    if (Test-Path -LiteralPath $sidecar) { Copy-Item -LiteralPath $sidecar -Destination $backupDir }
}
$filesDir = Join-Path (Split-Path -Parent $dbPath) 'files-demo'
if (Test-Path -LiteralPath $filesDir) { Copy-Item -LiteralPath $filesDir -Destination $backupDir -Recurse }
Write-Output "备份位置：$backupDir"
```

上传原文件在**实际数据库同级的`files-demo`**，不只在数据库里。多个数据库在同一目录时会共用该文件目录，不能因其中一个库不用了就清空整个目录。固定场景另保留`.scenario.json`。备份和本机配置可能敏感，按实际授权私下移交，不能推到GitHub。

### 6.3 显式升级与恢复检查

确认DATABASE_PATH仍指向目标旧库后：

```powershell

.\.venv\Scripts\python.exe -X utf8 -m medplatform db-status

```

### 6.4 换电脑/换Windows账户的限制

Git仓库不含原电脑`.env`、虚拟环境、运行库、上传文件或会话凭据。clone完没有原演示数据是预期行为，不是同步丢失。

## 10. 常见问题与处理

| 现象 | 先检查什么/如何处理 |
| --- | --- |
| 找不到python/py，或setup版本错误 | 确认安装的是x64 CPython3.14.10，重新打开终端；用已确认的解释器绝对路径创建venv，分别核对基础Python和venv版本 |
| ModuleNotFoundError | 在工程根，用`.venv/Scripts/python.exe`运行；确认同一解释器已安装requirements，勿从medplatform子目录启动 |
| pip下载失败/版本不可用 | 核对Python/位数/锁定版本、包源网络或完整wheelhouse；不关闭证书校验、不随意升级全套依赖，记录实际错误 |
| 网页打不开/8000占用 | 查看服务终端是否仍运行；只访问127.0.0.1。确认占用进程后协调停服，或在启动前显式改`$env:PORT='8010'`并访问同端口；不盲杀别人的进程 |
| 页面提示存储未就绪、API503 | 核对DATABASE_PATH、是否init或已显式migrate、已执行迁移是否和代码一致；普通serve不会修库，不能删库假通过 |
| 网页看起来没有原数据 | 检查是否换了库、打开了新终端丢失环境变量、换了患者或日期；库/文件不随Git上传，先看路径而不是重跑生成器 |
| 生成器拒绝覆盖已有库 | 正常保护；恢复旧演示直接serve原库，完整重演选新子目录。已有场景补录用--add-late-report并保留manifest |
| 401/会话失效 | 会话8小时或已退出，重新选择虚构身份；不是要求输入GitHub密码 |
| 跨电脑敏感回执503 | 核对DPAPI原Windows账户/机器条件；不能承诺旧Cookie/游标可迁移，保留旧库并验证新登录，不解密失败后另造旧成功回执 |
| 家人403/对象404 | 检查实际关系、精确Scope/到期/撤销和当前对象；本人限定动作不能通过扩大Grant绕过 |
