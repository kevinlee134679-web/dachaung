## 2. 项目与阶段成果

O 持有身份、患者、精准 Grant、授权共享范围、描述性画像与正式用药计划。A 持有用药/指标证据、五类统计、不可变摘要和显式任务执行。B 持有支持对话、描述线索、知识投影、模式与邀请，B23/B24 复用 C 的正式服务提交和状态。C 持有资源、服务草稿、授权确认引用、唯一正式服务、反馈、同辈及积分账本。统一入口提供认证、四字段 Envelope、同源 CSRF 和公共幂等回执。全平台审计实测 154 个 HTTP API，其中部分入口体现安全拒绝及阶段边界。 [正式审计报告](../全平台/S04-S05整体审计与S00-S03回归验收.md)

## 3. 获取代码和安装

1. 解压接力包到专用目录。用 PowerShell 的 `Get-FileHash -Algorithm SHA256 -LiteralPath '实际文件'` 核对 [接力包说明](接力包说明.md) 提到的完整性清单。
2. 推荐从同包 Git bundle 恢复已验证的本地完整历史。在一个准备好的工作区打开 PowerShell，将路径改为实际解压位置。目标目录已存在时先保留并核对。

```powershell
$bundle = 'C:\实际解压位置\dachaung-handoff-v2.0\code\dachaung-develop.bundle'
if (Test-Path -LiteralPath '.\dachaung') { throw '目标目录已存在，请先核对。' }
git clone --branch develop --single-branch $bundle dachaung
if ($LASTEXITCODE -ne 0) { throw '恢复失败，请核对 bundle 路径与 SHA256。' }
Set-Location -LiteralPath '.\dachaung'
git rev-parse HEAD
git status --short --branch
git merge-base --is-ancestor c46a46912a8ac47c8732b824831943f6fbd23dd5 HEAD
if ($LASTEXITCODE -ne 0) { throw '缺少已审计应用代码。' }
```

3. 对照 `发放清单.json` 核对 bundle 恢复的完整 HEAD。bundle 克隆的 origin 是本地文件。首次演示保持即可。团队协作时可在新克隆中经核对执行 `git remote set-url origin https://github.com/kevinlee134679-web/dachaung.git`。
4. GitHub 可读时也可在空目录执行 `git clone --branch develop --single-branch https://github.com/kevinlee134679-web/dachaung.git dachaung`。应对照远程已核验哈希。若远端前进，核查差异；需要精确复现实测基线时，在新克隆中执行 `git switch --detach c46a46912a8ac47c8732b824831943f6fbd23dd5`，保留正常开发分支。远端可能仅有运行代码，此时继续用解压包内文档。
5. 安装官方标准 x64 Windows CPython 3.14.10 和 Git；需跑完整前端验证时准备 Node.js 24。Edge 用于实际验收。工具安装后新开终端检查版本。 [Python 3.14.10](https://www.python.org/downloads/release/python-31410/) · [Git for Windows](https://git-scm.com/install/windows) · [Node.js](https://nodejs.org/en/download)

在项目根目录安装到新虚拟环境。已存在的解释器和虚拟环境先核对，失败保留终端原始错误。

```powershell
py -3.14 -X utf8 -c "import sys,struct; print(sys.version); assert sys.version_info[:3]==(3,14,10) and struct.calcsize('P')==8"
if ($LASTEXITCODE -ne 0) { throw '请先确认 CPython 3.14.10 x64。' }
if (Test-Path -LiteralPath '.venv') { throw '已有虚拟环境，请先核对。' }
py -3.14 -X utf8 -m venv .venv
if ($LASTEXITCODE -ne 0) { throw '虚拟环境创建失败。' }
$demoPy = '.\.venv\Scripts\python.exe'
& $demoPy -B -X utf8 -m pip install -r requirements.txt
if ($LASTEXITCODE -ne 0) { throw '锁定依赖安装失败。' }
& $demoPy -m pip check
if ($LASTEXITCODE -ne 0) { throw '依赖校验失败。' }
```

如果系统只有 `python` 或明确的 Python 安装路径，用已经检查的那个解释器替换 `py -3.14`。直接调用虚拟环境里的 Python 即可。21 个锁定包由 pip 安装，网页没有前端构建步骤。完全离线安装需额外准备同类 Windows/Python 的整套已校验 wheel，包内有离线源码和文档。

## 4. 初始化一个专用演示库并启动

在工程根、刚才的 PowerShell 中执行。已有演示直接看第 6 节。示例用 8000，若已被占用改用空闲端口并同步修改浏览器网址。使用绝对数据库路径，保留已有 `.env` 和旧库。首次 seed 提供虚构账号、目录、受控主体、同辈小组、零余额账户及权益目录。

```powershell
$env:APP_ENV = 'test'
$env:AUTH_MODE = 'demo'
$env:LLM_MODE = 'mock'
$env:DIALOGUE_PIPELINE = 'single_pass'
$env:HOST = '127.0.0.1'
$env:PORT = '8000'
if (Get-NetTCPConnection -LocalPort ([int]$env:PORT) -State Listen -ErrorAction SilentlyContinue) {
    throw '端口已占用，请选择空闲端口并修改上面的 PORT。'
}
$demoFolder = Join-Path (Get-Location).Path ('test-output/handoff-' + [guid]::NewGuid().ToString('N'))
New-Item -ItemType Directory -Path $demoFolder | Out-Null
$env:DATABASE_PATH = Join-Path $demoFolder 'demo.sqlite3'
$demoPy = '.\.venv\Scripts\python.exe'
foreach ($step in @('init-db','seed-demo','seed-support-catalog','seed-support-recipients','seed-peer-groups','seed-points','seed-rewards','db-status')) {
    & $demoPy -B -X utf8 -m medplatform $step
    if ($LASTEXITCODE -ne 0) { throw "演示初始化失败：$step" }
}
Write-Output $env:DATABASE_PATH
& $demoPy -B -X utf8 -m medplatform serve
```

在浏览器打开 `http://127.0.0.1:8000/`，实际端口若变更则替换 8000。健康页为同一地址下的 `/api/v1/health`，检查应用 `0.5.6`、存储就绪和 schema 依赖可用。精确 schema 版本 `0014` 由 `db-status` 输出。通过启动时明确的完整数据库路径和实际数据复核库的归属。

## 5. 网页演示顺序

用演示患者甲（`demo-patient-a` / 患者 `demo-patient-a-self`）。患者乙可检查跨患者隔离，演示家人需有明确绑定和各项授权，演示管理员用于受控模拟操作。切换前先退出并确认服务端会话失效。

1. **S02 身份、问卷和计划。** 进入「我的 → 八题问卷」，保存并提交完整问卷。打开画像结果，明确生成描述性结果。到「用药管理 → 药品资料/资料核对」创建虚构药品与草稿，由本人核对正式发布。选择将来几分钟或依页面默认的合法生效时间。可在另一个会话演示家庭绑定、授权和撤销。
2. **S03 服药与报告。** 从到时的「今日安排」进入服药记录，选择实际时段，提交、读取及追加更正。在「我的 → 用药报告」填与病例一致的北京时间起止日期，结束日不含，点击「明确刷新统计与摘要」。初次空库未准备正式计划或未到时不会直接有统计。五类按实际证据区分，本人已服进入分子，以已到时有效时段为分母。配置提醒后由受控显式维护和 A36 推进模拟提交，页面投递状态与送达分开。 [S03交接](../S03/运行与交接.md) · [任务调度](../任务调度说明.md)
3. **S04 支持对话。** 进入「支持服务」，开启普通对话，发送虚构的日常支持请求，试问缺乏可信资料的医学问题。查看谨慎回应及邀请，明确拒绝，再进入极简模式、刷新、明确恢复。检查历史与模式同步。 [S04交接](../S04/运行与交接.md)
4. **S05 服务与反馈。** 进入「支持服务 → 社会支持」。查看目录演示标记和版本，依据既有画像筛选，选择资源，手工保存草稿。本人核对精确修订和共享范围，使用有受控接收主体的模拟资源确认，再创建唯一正式服务。记录编号，查看派发状态及历史。由演示管理员从社会支持演示控制台按受控操作执行派发、模拟处理和完成。患者刷新核对，按实际反馈资格提交与更正三维反馈。对方范围无有效 Grant 时应显示受控拒绝。
5. **S05 同辈与积分。** 进入「匿名同辈」，已准备合法模拟服务的本人可明确自愿加入；换虚构会话再登录会从服务器恢复本人的匿名记录，退出后保留历史。受控演示管理员按可用入口审核。进入「积分权益」，试读余额、规则、流水和五档权益，空账本初始 0，兑换金额不足应拒绝。完成合法来源及管理员显式核验后才可演示正向核奖、兑换和履约。状态未知先查原订单；限定退分会保留原扣减与退款流水。 [S05各批详细操作](../S05/运行与交接.md)

## 6. 停止、重新启动和故障处理

在自己的服务终端按 Ctrl+C。再次启动时在同一工程中恢复第 4 节六个运行设置和初次记下的**同一个绝对** `DATABASE_PATH`，先 `db-status`，再 `serve`。保留数据库和其同级 `files-demo`；固定历史场景还需同级 manifest。已有库只启动，无需再执行初始化或 seed。要双击启动，可让首次接手 Codex 写入工程内 Git 忽略的 `private/handoff-bootstrap/启动演示.cmd`，其中固定实际解释器、项目根、模式、库路径、端口并检查退出码。只要项目或库搬家，就在新路径重新验证入口。

| 现象 | 处理 |
| --- | --- |
| 找不到 Python 或模块 | 先核对已安装的 x64 解释器、当前工作目录和虚拟环境，依锁文件补齐、运行 `pip check`。 |
| 端口被占用 | 核对是否自己的同工程同库服务，可复用才复用；其他应用使用新端口。 |
| 503 / schema 不匹配 | 核对目标库路径、版本及校验；需要升级时先停服务并保留原库和其同级文件，在副本上显式 `migrate` 再 `db-status`。 |
| 数据看似丢失 | 先查库路径、患者和日期。健康页就绪不能单独证明打开的是原库。 |
| 401/403/404 | 检查会话与当前精确 Grant。本人限定动作须由本人做。受保护的旧 Cookie、回执或游标使用原 Windows 用户环境的 DPAPI，跨设备新登录。 |
| 409 或响应丢失 | 先读取原提交、业务 ID 和最新状态。重试用同一操作键和相同内容，已明确冲突时根据最新版本和页面指引准备新操作。 |
| 空报告、摘要 stale | 核对正式计划和实际原窗口，管理员按需要维护，再手动刷新。旧摘要仍保留真实时点和签名语义。 |

旧库和未知 schema 的处理需要保护数据。备份登记原路径和校验，迁移按 `migrations/` 的单一编号追加。完整校验失败时保留现场，交负责人核对代码和备份。
