## 修复内容

原 `medplatform/protection.py` 只接受 Windows，Linux 登录返回 `503 SENSITIVE_RECEIPT_UNAVAILABLE`，进而阻断后续业务。现在 Windows 继续使用原生当前用户 DPAPI，原 DPAPI 实现及其载荷格式保持原字节；Linux 使用新增 `linux_protection.py`，通过 cryptography 的 AES-256-GCM 保护会话、敏感回执和游标。接口、授权、幂等和业务规则不变，无数据库迁移。

Linux 保护载荷有明确版本前缀、每次随机的 96 位 nonce，并将格式版本、当前 UID 和业务上下文绑定为认证附加数据。`session:`、`receipt:` 和游标之间不能串用。没有明文或固定共享密钥后备路径。Windows 与 Linux 的旧敏感载荷不自动互解，不能把跨平台复制数据库当作敏感会话迁移完成。

密钥由第一次明确的受保护写入创建，位于工程的 `private/local-protection/uid-<当前UID>/key-v1.bin`，不在 SQLite 或 Git 中。密钥为 32 字节，目录必须 0700、密钥必须 0600，所有者必须是当前 UID；拒绝符号链接、硬链接和可由其他用户写入的父目录。首次初始化用目录文件锁串行化，多个进程共用同一密钥。读取不生成密钥；初始化标记防止密钥丢失后被新写入静默替换。篡改、上下文不符、缺失依赖、密钥异常或权限不符均返回既有 503，事务不留下半个登录。

这是以当前用户文件权限保护本地密钥的实现，不等同于 DPAPI 或生产密钥托管。备份当前 Linux 演示时，除数据库、同级文件和场景 manifest，还须单独妥善保存原密钥目录；密钥不能进入代码、截图、日志或公开交付包。缺失或损坏时保留现场，恢复可信原密钥并核对 UID/权限。没有原密钥就不能恢复旧敏感载荷，不能通过删除初始化标记或改明文绕过。

依赖锁新增 Linux 条件项 cryptography 50.0.2、cffi 2.1.1、pycparser 3.12。Linux 共 24 个项目锁定包，Windows 继续选择原 21 个包。本轮使用 CPython 3.14.10 x64、Node 24.22.1；`pip check` 通过。未重跑 Windows/Edge，不能将本轮 Linux 验证写成新的 Windows 实测。
