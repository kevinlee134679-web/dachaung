# S00：CAS与支持强度保留能力、延期适配方案（draft01）

2026-11-16，Asia/Shanghai。用户提出：在CAS和支持强度映射暂未适配时保留两项能力，先推进开发，后续仍可修改。本文件把该需求整理为可评审方案；**以下新增设计均为建议、待确认、未实现**。不把本次询问视作确认全部FQ或明确执行S01，不编写应用业务代码，不调用付费API。

## 1 已确认、用户需求与本轮建议

| 类别 | 内容 |
| --- | --- |
| 已确认 | CASResult已有status/value/reason/model_version/preprocessing_version，未适配value=null并说明原因；O画像与CAS分开，原始回答及历史画像保留 |
| 已确认 | B Assessment无确认评分方法时score=null；原话、自评、模型线索、A客观记录分开；支持强度不是临床风险等级，用户自主操作与自动决策分开 |
| 用户本轮提出的需求方向 | 保留CAS和支持强度能力，允许后续适配/修改，尽量让其他开发继续；不删除功能、不提前硬编码缺依据的算法 |
| 本轮建议 | 先实现采集/保存/查询/显示/方法适配边界，再独立接入模型或规则；具体内部接口、未配置状态、新字段和启用规则须评审 |
| 尚未确认 | F00其余FQ、真实CAS输入映射/模型/验证、BU02量表及支持强度映射；本文件具体设计；应用阶段尚未启动 |

## 2 可以先做什么（按原阶段授权实施）

| 能力 | 后续先实施的部分 | 算法未就绪时的行为 | 唯一业务维护方 |
| --- | --- | --- | --- |
| CAS | 保存原始回答、问卷/输入版本，保留CASResult及页面区域，建立可替换计算适配边界 | status=unavailable、value=null；reason明确方法未适配，未启用模型/预处理版本保持null；不显示0分或伪造指数 | O，研究方法由项目组提供/审核 |
| 障碍画像 | 先完成问卷、描述性影响因素、结果/历史查询；独立保留规则分类适配点 | 没有确认分类规则时primary_type=null、descriptive/insufficient；模拟画像走已确认O fixture，不据CAS缺失删除整个画像能力 | O |
| B评估 | 保存真实原话/自评/线索、证据及方法版本，先做已确认的描述性记录 | 无评分方法不产生总分、概率或诊断；缺失原因可读 | B4 |
| 支持强度 | 保留策略输入、证据快照、映射适配边界、结果与配置版本及页面说明 | 自动映射明确未配置，不把none/low当“未知”的替代值，不生成自动升级或第三方联络 | B5 |

这是未来阶段的实施顺序建议，不是当前已实现清单。尚未确认的画像分类映射、自动决策或接口增量不能因开发其他部分而自动生效。任何依赖未知算法的动作明确未就绪，不能写假成功接口冒充已经实现。

## 3 可替换边界建议（不新增对外URL、不另建工程）

CAS适配接收O保存的精确响应/问卷版本和已确认输入映射版本，返回现有CASResult；资料不足与适配器错误分别说明。研究模型的预处理使用固定已验证参数，不对单个新患者重新fit，不拿A本人确认比例代替CAS。

支持强度适配接收B已有输入快照、患者明确偏好、当前获准上下文和配置/规则版本，返回有可用状态、原因和来源的内部映射结果。规则只产出候选决策，实际执行仍经过B业务检查、O授权和A/C原有边界，不让LLM直接控制强度/共享/模式/积分。

建议内部映射结果逐字段如下，版本暂为deferred-draft01；这是待确认对象，不是已经扩展B API：

| 字段 | 类型 | 必填/可空 | 默认 | 枚举/范围/语义 | 生成方 |
| --- | --- | --- | --- | --- | --- |
| availability | string | R/N | not_configured（无适配方法时） | not_configured/disabled/insufficient/evaluated/failed；描述本次映射可用性 | B5适配器及运行配置 |
| support_intensity | string | R/Y | null | none/low/moderate/high；只有evaluated时可非null，none只表示已评估后无需干预 | 已确认规则适配器 |
| method_version | string | R/Y | null | 1—128字符；无实际启用方法不造版本 | B5配置/适配器 |
| reason | Reason | R/Y | null | availability非evaluated时必须说明；不保存思维链 | B5 |
| evidence_refs | EvidenceRef[] | R/N | [] | 复用B完整定义，引用本轮真实可访问证据 | B5 |
| evaluated_at | DateTime | R/N | 服务器本次时刻 | 沿用统一时钟；不能伪称过去已运行 | B5 |
| is_simulated | boolean | R/N | 实际适配环境 | 不能用模型mock标记掩盖真实患者/渠道来源 | 受控适配 |

availability=failed与not_configured分开；方法失败不偷偷降回演示规则。没有映射不抹掉患者求助/偏好，也不由LLM“补齐”low/moderate/high。

## 4 现有B契约的兼容点（必须单独确认）

当前已确认Intervention.support_intensity为R/N字符串，枚举none/low/moderate/high，没有“尚未配置”取值。**不能直接向它写null、另加unknown或用none伪装未知。**

建议先将上述内部结果与可执行Intervention分开：未得到合法映射时，不创建依赖自动强度的可执行干预；页面仍需要读取能力未就绪的真实说明。对外如何返回该能力状态须作为新的B契约增量完整定义。

优先建议保留既有Intervention字段含义，在策略查询的响应视图单列映射可用状态；具体挂载对象/完整返回、成功和未就绪失败例子、消费者升级影响待后续接口卡确认。若改选让原字段可null，则属于明确的字段兼容变更，也要新B版本、迁移及前后端同步升级。本文件不自行选择未提出完整卡片的线上结构。

因此CAS算法及支持强度方法未完成本身不要求停做共用底座、输入记录和独立用户功能；实现B完整自动策略闭环前，仍需确认未配置状态的对外契约和可执行动作边界。不能把“可先开发”解释为所有必要契约均已完成。

## 5 后续怎样替换和修改

| 变化 | 建议处理 |
| --- | --- |
| 新增/替换CAS模型或预处理 | 固定输入映射/模型/预处理版本，先用隔离虚构样例验证；经确认后启用对应适配器，不改网页采集和正式计划维护方 |
| 更换支持强度规则 | 新增方法/规则版本及输入适用条件，验证低/中/高映射和缺失/冲突/拒绝情形；经确认后切换，执行仍受原授权/频率等约束 |
| 新增研究题目或必需特征 | 新问卷/映射版本，旧回答保留且可显示缺项；不从旧八题猜填原研究变量，不暗中增加必答题 |
| 修改存储结构或输出字段 | 新增schema迁移/API契约版本与消费者适配；保留旧记录和旧结果，不承诺任何改动都只需改配置 |
| 对旧输入使用新方法重评 | 明确选择原输入快照并生成新的结果/方法版本；原结果不覆盖，不自动重发干预、联系第三方或重算积分 |
| 停用或回退方法 | 新操作记录启停/回退，不删除历史；不能把历史预测改成另一个模型输出，不能把故障伪装为成功 |

无需先准备真实付费模型才能开发无密钥模拟/数据流程；真实CAS适配、真实强度依据及验证完成后单独接入，不把模拟通过当方法有效。
