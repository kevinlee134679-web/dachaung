# S01 存储基础数据字典

维护分工仍为O权威身份/授权/画像/正式计划，A统一存储及迁移，B定义沟通策略与B2共用知识，C维护唯一服务与积分账本。本页是S01实际表的内部存储映射，不替代已确认的对外对象，不冻结后续业务字段。所有运行库均忽略上传。

| 表 / 迁移 | 实际字段与用途 | 约束与边界 |
| --- | --- | --- |
| schema_migrations / 初始化器 | version、parent_version、name、checksum、applied_at、app_version | STRICT；版本主键，顺序/父版本/文件原字节SHA256逐项检查；显式迁移登记UTC时间 |
| operation_audit / 0001 | operation_id、account_id?、patient_id?、operation、outcome、occurred_at、data_environment | 技术事务结果基础表；不把它当B/C业务事件、不可逆投递证明或完整敏感幂等回执 |
| dose_slots / 0001 | dose_slot_id、patient_id、data_environment、plan_id、plan_version、plan_entry_id、medication_id、scheduled_at、status、source_rule_version、is_simulated | O已确认单药原子DoseSlot的存储引用；按患者/环境/计划/版本/条目/应服时间唯一，状态active/superseded/cancelled继承原契约；S01不生成/取消slot、不发布计划 |
| source_events / 0001 | event_id、patient_id、data_environment、event_kind、source、source_subject_id、source_event_id、evidence_type?、occurred_at、received_at、reporter_account_id?、device_id?、original_payload_json、is_simulated | event_kind=medication/measurement，source=manual/box/wearable；来源ID与A事件ID分离，患者/环境/来源/可信来源主体/来源事件ID唯一；原始JSON对象不被清洗或推断覆盖 |
| event_revisions / 0002 | event_id、revision、change_kind、occurred_at、payload_json、reason?、replaces_revision?、actor_account_id?、created_at、is_simulated | 事件+修订主键；原始修订1，更正/撤回为后继修订且需原因、前驱存在；与原事件模拟标志一致。迁移为0001现有数据补原始修订，不删原记录 |
| evidence_slot_links / 0002 | event_id、event_revision、patient_id、data_environment、dose_slot_id | 事件修订只能关联一个slot，同一slot允许多个来源；复合FK同时约束事件、slot属于同一患者/环境；不实现自动匹配或重新归并 |

`?` 为可空，没有把缺失设置成零的默认值。演示环境为demo/is_simulated=1，预留real/0隔离标志；当前可信读适配只准demo，真实模式关闭，保留列不表示实际接入真实患者。JSON内指标值、单位与missing_reason沿用已有指标字段，测试确实分别保存null和0；接收端字段/来源/患者归属校验在后续获准业务模块完成，不能将任意JSON直接暴露为网络写入。

手工来源必须有reporter_account_id且无device_id；设备来源反之；内部source_subject_id等于该可信主体，用于稳定去重命名空间。服药证据使用既有self_report/family_report/box_opening/device_inference；指标事件evidence_type为null。来源推断在已确认规则内由后续适配端完成，本阶段没有客户端来源选择接口。

同库事件/修订/slot使用外键并始终启用foreign_keys；尚未实现的O患者/账号/计划及外部设备引用没有假造外键表，后续由O权威适配核验归属、补新增迁移。患者时间和slot关联有索引，不为每列机械建索引。缺失质量、有效证据优先级、分母/分子、五类统计、CAS、B快照、C账本、任务/租约等未实现，不创建空业务表或伪结果。

0001/0002是本次首次提交的迁移，发布后只允许新增0003及以后；.gitattributes对SQL禁用换行转换，跨Windows检出校验和保持不变。迁移事务同时包含结构、回填和版本行；不使用会隐式提交的executescript。失败/未知库/更高版本/降级/历史文件篡改拒绝操作；不会清库求通过。
