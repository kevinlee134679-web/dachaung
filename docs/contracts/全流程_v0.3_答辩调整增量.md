# 全流程 v0.3：答辩调整增量

2026-11-26，Asia/Shanghai。依据合并后重构与调整决定。下列各节取代全流程_v0.1、全流程_v0.2及各模块有效增量中的对应约定，未列出的确认内容继续有效；原确认文件、旧示例与历史结果不改写。契约 flow-v0.3，表结构变更见迁移 `0022_remove_points_rewards.sql`。

## 1 删除积分权益、社会支持推荐与指标记录

- **积分权益与周期回顾取消**：域 C 取消激励积分账户、周期审核、结算对账、积分流水、兑换品目录、兑换订单与履约回执；取消接口 `C22`—`C33`、`C38`、`C39` 及 `points:*`、`rewards:*` 授权范围；删除配置项 `DEMO_FULFILLMENT_RECEIPT_SUBJECT`、`DEMO_FULFILLMENT_RECEIPT_TOKEN` 与履约回执认证分支。迁移 `0022_remove_points_rewards.sql` 删除 `c_redemption_feedback` 等 13 张积分与兑换表。
- **社会支持推荐取消**：域 C 取消 `C01` `GET /api/v1/patients/{p}/support-recommendations`、查询参数 `need` 及资源查询参数 `channel=rewards`；保留 `C02`、`C03` 资源目录及服务草稿、知情同意、正式服务、服务反馈与匿名同辈互助（含 `C41` `GET /api/v1/peer-memberships/me`）。
- **指标记录与趋势取消**：域 A 取消手动与设备指标采集、查询及趋势接口（`A13`—`A15`、`A30`）及 `measurements:read`、`measurements:write` 授权范围；取消 `A31` 摘要中的 `measurement_overview`、`DeviceEventInput.event_kind` 指标分支及 `measurement_missing`、`unknown_unit` 演示场景。`source_events` 表结构保留，通用读取与修订接口仅返回 `event_kind="medication"` 事件。
- **公共执行任务种类收窄**：`TaskCreateInput.kind` 取消 `fulfill_reward`（`refresh_statistics`、`refresh_summary` 已由 `flow-v0.2` 取消）。

## 2 O 问卷与画像重做

- **单版本问卷**：仅保留 `initial-cas-review-v1`（`backend/medplatform/profile/cas_questionnaire.json`），取消 `initial-v0.1`、`initial-cas-review-v1-core1` 及 `O15` `GET /api/v1/questionnaires/initial` 的 `version` 查询参数。`O15` 返回去掉 `result_notes` 的定义。
- **作答结构**：取消每题独立作答状态字段，将「无法判断」作为 `code="unknown"` 选项保存在各题作答值中。`O16` `ResponseCreate` 仅保留 `supersedes_response_id`，新建替代答卷从空白初始化；`O17` `AnswersPut` 为 `{expected_revision, answers}`，按题号整段校验（含 `visible_when`、`exclusive` 与 `main_barrier` 归属）并替换保存。
- **画像输出与复用**：`O22` `POST /api/v1/patients/{p}/profiles` 使用评估方法 `cas-questionnaire-v2`，返回 `cas_observed`（本人作答、确认同次经历且 Q1–Q3 有效时计 3–15 分，否则 `insufficient`）、`cas`（配置 `CAS_RETRAINED_BUNDLE`、安装 `cas` 依赖组且本人完成 Q5–Q8 并符合 `stable_experience != "否"` 时为 `estimated`，缺项、非本人或不适任时为 `insufficient`，未配置模型时为 `unavailable`）、`cards`（按 Q1、Q2、Q3、Q4、Q6、Q7 输出 `good`/`neutral`/`attention` 卡片与建议）及 `factors`；取消 `cas_predicted`、`research_group`、`demo_classification`（`primary_type`、`reported_matching_types`）。同一答卷在方法版本与当前模型版本不变时复用已有画像。
- **最新提交读取**：新增 `O32` `GET /api/v1/patients/{p}/questionnaire-responses/latest-submitted`（仅本人可用，返回最近一次已提交答卷的 `response_id`、`submitted_at` 与对应 `profile`，未生成时 `profile` 为 `null`，无已提交答卷返回 404 `PROFILE_NOT_AVAILABLE`）；取消 `O20` `GET /api/v1/patients/{p}/profiles/current` 的 `source` 查询参数。
- **模型依赖与加载**：`torch`、`numpy` 由 `backend/pyproject.toml` 的 `cas` 依赖组锁定；`CasModel.load` 直接加载 `preprocessing.json` 与 `ensemble.pt`，不再执行启动 SHA-256 校验与对照样例重放。

## 3 A AI 病历识别与漏服原因

- **AI 病历识别（`A42`）**：新增 `A42` `GET /api/v1/files/{id}/medication-recognition`（本人或具备 `files:read` 授权的家属可调用），取代本机 PDF 文本预览接口 `GET /api/v1/files/{id}/medication-preview`。未配置模型客户端时返回 `status="unavailable"`；配置后，PDF 经 `/files`（`purpose="text_recognition"`）上传并引用 `file_id`，PNG/JPEG 以 base64 `image_url` 调用 `/chat/completions`，返回 `{status, medications, allergies, diagnosis}`（`status` 取 `unavailable`/`failed`/`no_candidates`/`ready`）。
- **漏服原因**：`A10` `MedicationEventInput` 与 `A16` `EvidencePayload` 新增可选字段 `missed_reason`（枚举 `forgot`、`not_with_me`、`ran_out`、`unwell_or_side_effects`、`not_needed`、`other`），仅当 `reported_status == "not_taken"` 时允许非空。

## 4 B 对话模型接入、危机前置检查与输出校验

- **模型接入与用量记录**：`LLM_MODE` 允许 `mock` 与 `real`；设为 `real` 时必须同时配置 `LLM_BASE_URL`、`LLM_MODEL`、`LLM_API_KEY`。`ChatModel`（`mode="real"`）调用 `/chat/completions`，超时映射为 `PROVIDER_RESULT_UNKNOWN`（`outcome_unknown=True`），空内容映射为 `PROVIDER_EMPTY_RESPONSE`，provider 用量记入 `calls[].usage`（`source="provider"`）；消息、生成与助手回复的 `is_simulated` 依 `adapter.mode == "mock"` 记录。
- **危机前置检查**：`Dialogue.run` 在调用模型前先检查本轮用户文本（`backend/medplatform/dialogue/crisis.py`），命中危机短语时直接返回固定安全提示，不调用模型。
- **放宽输出校验**：`backend/medplatform/dialogue/completion.py` 的 `validate_completion` 仅要求根节点 JSON 对象包含非空且长度不超过 2000 的 `assistant_reply`；`support_focus` 与 `communication_strategy` 不合法时降级或丢弃；`DifficultyCue` 仅保留 `category` 与 `label`（取消 `evidence`、`source_message_id` 与原话白名单校验）；`Readiness` 仅保留 `state`；`knowledge_citations` 校验保持不变。
