# 虚构全平台演示脚本

先按 [运维文档](运维.md) 准备环境。所有药品、剂量、日程、问卷和发言都只作虚构流程演示，不使用真实患者资料。默认服务回环本机，未经配置不是公网网站。

1. **首次使用**：明确 `init-demo` 后 `serve`，浏览器打开127.0.0.1:8000。选演示患者甲，登录；五个导航为首页、用药管理、支持服务、积分权益、我的。
2. **O信息链**：填写八题问卷，逐项选择真实的虚构答案（未知就“不清楚”），明确提交，生成描述性画像。展示CAS尚未适配。用药管理→药品资料/病历资料→资料核对，手工录入虚构药品、剂量原文/单位和日历；保存并提交草稿；本人核对后才确认正式安排。家属无发布按钮。
3. **A证据与报告**：查看今日安排，分别报告服药情况与指标，0、缺失、未知单位保持原值。我的→用药报告，明确刷新统计与摘要。没有已到时计划时段时分母0、比例不可计算，不能展示虚构达标率。通知/任务须管理员或独立worker明确执行，页面关闭不保证系统推送。
4. **B对话与减负**：支持服务→开始自由对话，输入“虚构情景：我担心副作用，只想倾诉。”；显示mock回复。主动使用极简模式，刷新仍保持，明确恢复普通模式。管理员在“我的”可选择mock STAR、零网络探测，患者另发一轮，再切回single_pass；旧轮流水线和历史不改。受控案例可演示STAR中途失败与原消息重试；超时结果未知必须查原记录，不能重置抹去。
5. **C社会支持**：社会支持→选择明确需求→查看匹配及原目录版本。查看药学咨询模拟资源→准备服务问题→保存草稿；浏览和草稿不会申请。本人只勾选必要共享类别并核对接收方，明确确认共享，然后明确提交正式服务。记录编号和派发任务编号。退出患者，管理员“我的”输入原任务编号，明确模拟派发；使用原服务编号按合法顺序记录处理中/完成。患者重新登录→服务记录→同一服务，填写三维自愿反馈。首页近期服务同步显示该权威状态，完成不代表临床有效。
6. **同辈**：患者支持服务→匿名同辈→可申请小组→准备本组申请→准备入组草稿，明确共享与本人自愿入组。待受理不能发言。管理员按原服务任务模拟派发并记录处理中，患者刷新原成员可交流；提交不含身份/诊疗信息的短文字待审。登记的moderator在“我的”输入小组编号，填写模拟审核说明，允许匿名公开；患者刷新看匿名文字，然后主动退出。展示原历史、当前交流已关闭。
7. **家庭**：患者“我的”→家庭授权生成单次限时绑定码，家属登录兑换，关系没有自动健康权限。患者明确勾选所需scope并保存；如只授对话历史，家属可以读取但不能代发/切换模式。患者撤销后，家属刷新和原接口会话立即失去该权限。
8. **积分与权益**：患者积分权益查看规则、原始来源、余额和历史；当周回顾需本人明确确认，核奖由受控管理员执行。没有来源时保持0分，不能为演示加余额。达到余额后本人明确兑换，管理员明确执行原履约任务，患者查看模拟管理文本。刷新保持原订单与扣减；自愿体验不重复核奖。必要专业支持不设积分门槛。
9. **恢复与交接**：分别Ctrl+C停止Web/worker，使用同一数据库重新serve，展示会话、服务、反馈、积分和模式历史。升级前停止全部写入，migrate --stopped先备份。不要再次init原库，不删除未知结果或历史来重演。

## 独立可重放的统计与积分场景

以下在已配置 Python 3.14 的环境中执行。数据准备通过显式可控时钟和真实业务 API，启动网页恢复正常实际时钟；不冒充连续多日现场观察。

```sh
python -B -m medplatform.demo.medication --database test-output/report-demo/demo.sqlite3
python -m medplatform serve --database test-output/report-demo/demo.sqlite3 --port 8001
```

患者甲→用药报告，按生成器输出的window_start/window_end选择北京时间日期，明确刷新：14个已到时段、10次本人确认，开盒证据独立。在另一个终端明确执行（同库新来源，不清空）：

```sh
python -B -m medplatform.demo.medication --database test-output/report-demo/demo.sqlite3 --add-late-report
```

刷新为11/14；同一迟到来源重复执行仍11/14，原as_of快照仍10/14。此场景专注A，未seed其他模块时其目录显示未就绪属于真实边界。

```sh
python -B -m medplatform.demo.points --database test-output/points-demo/demo.sqlite3
python -m medplatform serve --database test-output/points-demo/demo.sqlite3 --port 8002
```

新隔离库：29个虚构计划日的普通API报告均为not_taken，说明如实记录也可获得正向积分；权威核验产生83分，重复核验不增加。患者登录明确兑换30分→53分，管理员明确执行履约任务，患者查看模拟文本。该场景只登记积分所需身份与权益；不向现有运行库插入余额，不代表服药成功或干预效果。目标已存在时生成器拒绝，不用删除原库重跑，选择新目录。
