# 新成员使用 GPT 自动接手指南 v1.0

日期：2026-11-17，Asia/Shanghai。文档版本：gpt-handoff-v1.0。

**给新成员：你先安装并登录能操作本机的 ChatGPT 桌面应用，在 Codex 中打开一个本地文件夹，然后复制第2节整段指令。让 GPT 完成克隆、安装、配置、验证和启动。** 不需要先自己安装 Python、Git 或逐条输入项目命令。

这份文件可以直接转发；第2节也另存为[首次接手指令.txt](gpt-handoff-v1.0/首次接手指令.txt)，可整份复制。首次执行的目标是把现有项目在**你的电脑**跑起来并读懂交接，不自动开发下一阶段。完整业务、页面操作、旧资料备份说明另见[人工查阅手册](接手使用与后续开发交接_v1.0.md)。

## 1. 你需要先做的三件事

### 1.1 安装应用并登录自己的账号

从[OpenAI官方下载页](https://chatgpt.com/download/)安装 Windows 桌面应用，登录你自己的 ChatGPT 账号，选择 **Codex**。旧版 Codex 应用更新后可能显示为 ChatGPT，其中仍有 Codex；以实际界面为准。[官方迁移说明](https://help.openai.com/en/articles/20001276-moving-to-the-new-chatgpt-desktop-app)

Codex可以使用ChatGPT账号登录，不需要为这次项目演示申请OpenAI API密钥。账号可用功能和额度按实际计划及管理员设置确定，不承诺无限免费使用；**项目自身的模拟运行无需付费API**。[官方登录说明](https://help.openai.com/en/articles/11369540-using-codex-with-your-chatgpt-plan)

### 1.2 打开一个自己的本地文件夹

在资源管理器中创建一个空文件夹，例如用户目录下的 `Projects`，在桌面应用的Codex中打开它，选择本机工作方式。GPT将在这里创建 `dachaung` 工程目录。你不必拥有原成员的D盘或中文目录。

需要让当前任务能读写这个工程位置、访问GitHub和官方软件/包下载地址，并运行本地命令。按应用提示完成必要授权；若学校或单位设备限制安装，需要设备管理员处理。**不需要为了安装而关闭防火墙、TLS校验或全局修改PowerShell执行策略。** Windows下Codex可原生使用PowerShell，其文件和网络访问仍受当前权限约束。[官方Windows说明](https://learn.chatgpt.com/docs/windows/windows-sandbox)

### 1.3 复制下一节，发送给 GPT

首次安装可能需要你亲自完成账号登录、系统授权/UAC或应用要求的确认。GPT应先把能自动做的部分完成，只在这些必须由你操作的地方停下，并说明具体位置。看到普通安装日志不需要逐条处理。

**如果你只有网页聊天：** 把本文交给它可以获得指导，但网页/云端终端中成功clone不代表代码已经在你的电脑上。请转到上述本机Codex任务后再执行；Work网页不能直接访问你的本机文件，Codex Cloud使用OpenAI管理的计算机。[官方本地与云端区别](https://help.openai.com/en/articles/20001275-chatgpt-work-and-codex)

## 6. 常见阻塞和最快处理办法

| GPT报告的问题 | 处理方法 |
| --- | --- |
| “没有本机终端/只在云端运行” | 改用桌面应用的本机Codex，打开本地文件夹，再发送第2节；无需让它先在云端装一套 |
| 要你登录或确认系统权限 | 在官方登录页/系统对话框亲自完成；然后回原聊天说“已完成，继续原接手任务” |
| clone超时/网络受限 | GPT保留退出码和现场，检查当前任务网络与GitHub访问；恢复后继续，不清工程、不关闭TLS、不反复盲试 |
| GitHub无权访问 | 确认自己的账号有读取权限；私有仓库由负责人邀请。以后推送另需写权限，与网站演示身份无关 |
| Python指向商店别名或别的版本 | GPT发现已安装的3.14.10 x64真实路径，必要时从官方安装；不要把3.15或32位环境混入原`.venv` |
| pip包下载失败 | 保留锁文件，核对网络、Python和wheel支持；可由负责人私下提供同Windows/x64/Python版本的锁定wheelhouse，由GPT核验后离线安装，不传虚拟环境 |
| 执行策略拦住`.ps1` | 直接调用虚拟环境Python，启动用本机`.cmd`，无需激活脚本或修改全局策略 |
| 网页打不开/8000被占 | 确认服务窗口仍运行、数据库/PORT一致；选空闲端口，不杀其他人的服务；fixture生成仍用8000配置 |
| 报告409或不是10/14 | 用manifest中的原七天窗口和“明确刷新统计与摘要”；核对指定库，不能把未准备结果显示为0 |
| 只有Node检查未完成 | 网站演示可继续；让GPT安装验证用Node再补检，报告中保留跳过事实 |
| 从Git没拿到原电脑的旧演示资料 | 属正常隔离：库、上传文件、`.env`和虚拟环境不在Git。新机重新生成虚构场景；需要原资料须另行授权、停服备份并私下移交 |

Windows用户DPAPI保护会话和敏感回执，旧库跨电脑或账户不保证可解密；不要为了迁移资料关闭保护、改成明文或把运行库提交到Git。安装接手首选新虚构库；已有真实资料的恢复流程见[人工查阅手册第6节](接手使用与后续开发交接_v1.0.md)。
