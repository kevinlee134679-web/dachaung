# 统一运行与备份（0.7.3 / schema0016）

0.7.3：Windows入口保留父启动链等待子进程并透传退出码；Linux沿用exec以便直接处理信号。Windows实机验收见根目录WINDOWS_ACCEPTANCE_README.md，默认双击WINDOWS_ACCEPTANCE.cmd；本轮真实Windows结果待回传，Linux预演不当作Windows通过。GitHub按负责人新安排在S06/S07验收后统一上传。

统一入口是根目录 `run.py`；`start.cmd`、`start.sh` 只是同一入口的系统包装。应用不依赖 Node 构建或 CDN，Node 仅用于前端回归。CPython **3.14.10** 已实际验证；入口检查3.14，依赖精确锁定于 requirements.txt（Windows21项、Linux24项）。安装时需要访问依赖源；本机演示无需模型密钥。

## 新环境

Windows 安装 CPython3.14（包含 py launcher），在项目目录运行：

```bat
start.cmd setup
start.cmd init-demo
start.cmd status
start.cmd serve
```

Linux 安装 CPython3.14 和 venv 支持，然后：

```sh
chmod +x start.sh
./start.sh setup
./start.sh init-demo
./start.sh status
./start.sh serve
```

默认地址 `http://127.0.0.1:8000/`，仅回环访问；这不是公网部署。默认数据库 `var/app-demo.sqlite3`。不需要自定义时无需创建 .env；需要时复制 `.env.example` 后本地修改，禁止上传。已有 `.env` 不会被入口改写。APP_ENV=local/test、AUTH_MODE=demo、LLM_MODE=mock；real、external、production 当前明确拒绝启动。

setup 只安装依赖；init-demo 才显式建库并依次登记身份、资源、接收主体、同辈、积分账户、权益、支持规则。它不会生成正式医嘱、服务申请或积分收益。目标库已经存在时拒绝初始化，不删除或重置；中途中断保留已建库，检查后用底层各 seed 命令继续，不自动覆盖。各 seed 的稳定编号与原有幂等语义保留。

独立环境或数据库路径含空格时使用引号：

```sh
python3.14 run.py --venv ".venv-review" setup
python3.14 run.py --venv ".venv-review" init-demo --database "test-output/review demo/demo.sqlite3" --port 8131
python3.14 run.py --venv ".venv-review" serve --database "test-output/review demo/demo.sqlite3" --port 8131
```

已有 .venv 若不是3.14，入口拒绝复用；选择新 --venv，不删除原环境。Windows 可用 `py -3.14 run.py ...`，参数一致。旧 scripts/*.ps1 与 `python -m medplatform` 底层入口保留，新增功能优先使用统一入口。

## 运行器与关闭

serve 不自动启动 worker、建库、升级或 seed。打开另一个终端，明确使用**同一库**：

```sh
./start.sh worker --once
./start.sh worker
```

自定义库必须同样传 --database；Ctrl+C 分别正常停止 web 和 worker。Linux SIGTERM 同样可停止。默认每5秒轮询，单库仅一个 runner；90秒租约、15秒续租、原节点7/28天、24小时时窗、重试/未知结果边界见 `../S06/运行与交接.md`。无系统通知、后台浏览器送达或真实机构履约保证。重启 serve 使用同一库恢复原会话与事实；不要重新 init-demo。

## 备份与旧库升级

先停止该库的所有 web、worker 和其他写入进程；`--stopped` 是操作者明确声明，入口不替你终止进程，也无法检测绕过入口的其他写入者。不要对仍在演示或执行任务的库声明已停止。

```sh
./start.sh backup --database var/app-demo.sqlite3 --stopped
./start.sh migrate --database var/app-demo.sqlite3 --stopped
./start.sh status --database var/app-demo.sqlite3
```

migrate **先成功备份，再升级**，无自动降级。备份默认 `private/backups/<UTC时间>-<随机号>/`，不进入Git；每次新目录，不覆盖。SQLite backup API包含已提交WAL，校验 integrity_check；另存原 files-demo、原Linux用户密钥和本地.env（存在时），manifest有SHA256。备份目录0700、文件0600（Linux）；Windows保存在当前用户私有工程路径，并自行保持账户目录ACL。符号链接和特殊文件拒绝复制；备份失败不开始迁移。部分失败目录只用于排查，不当成完整备份。

已实际验证0014→0016保留80张旧业务表，0015→0016保留STAR检查点，DDL失败事务回滚；早期迁移文件不改。Windows旧DPAPI密文不能在Linux解密，不能因升级成功声称跨系统历史凭据可用。

恢复时保持所有写入者停止：先核验 manifest 每个文件哈希，在**新目录**放置 database.sqlite3 与对应 files-demo，再以该新路径运行 status。必须保留原 Linux UID 和原项目 private/local-protection/uid-*/key-v1.bin、初始化标记；恢复原密钥前先保存当前密钥，不覆盖或生成替代钥匙。Windows DPAPI需要原用户/机器上下文。异机/跨系统的已有凭据迁移未实现。切回旧schema备份还需要匹配旧代码；新版 status 不会接受旧schema。原库和旧备份保留，未实现自动危险覆盖式 restore。

## 回归、结构与排错

```sh
./start.sh test
./start.sh inventory
```

test 先检查依赖，Node缺失明确失败；Python测试内执行前端Node用例，不重复加总。inventory 在临时空库运行全部迁移，导出实际85表和154个API的输入Schema；不读取患者运行库。Windows入口本轮做静态检查；当前新增入口的运行验证环境为Linux，不能当成已跑Windows。

缺库/旧库/迁移校验错误返回失败，不通过自动建空库掩盖；端口占用时先找原服务，不 killall。敏感保护503检查原用户、0700/0600、原密钥及备份，不删除 initialized-v1 或改成明文。模型结果未知保留原轮核查，不重置案例抹去；服务/兑换未知查原记录，不能重复派发或扣款。隔离重放选择新的 --database 路径，原演示数据不清除。
